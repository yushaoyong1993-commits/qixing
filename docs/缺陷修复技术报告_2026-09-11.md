## D-01 删除活动未级联清理轨迹点与分段（严重：数据完整性）

**发现用例**：ST-D02 —— "删除活动应级联删除轨迹点与分段（无孤儿数据）"

**现象**：删除一条活动后，`activities` 行被删除，但 `track_points` 与 `laps` 表中该 `activity_id` 的记录仍在，成为孤儿数据；数据库体积只增不减。

**根因**：`ActivityRepository.deleteRide` 只执行了对 `activities` 的删除：

```dart
Future<void> deleteRide(int id) {
  return (_db.delete(_db.activities)..where((t) => t.id.equals(id))).go();
}
```

**影响**：数据完整性受损；长期使用导致库体积膨胀；`track_points`/`laps` 与活动表不一致。

**修复**：

```dart
/// 删除活动（级联删除其轨迹点与分段，避免孤儿数据）
Future<void> deleteRide(int id) async {
  await (_db.delete(_db.trackPoints)..where((t) => t.activityId.equals(id))).go();
  await (_db.delete(_db.laps)..where((t) => t.activityId.equals(id))).go();
  await (_db.delete(_db.activities)..where((t) => t.id.equals(id))).go();
}
```

**验证**：ST-D02 —— 删除后 `rides()` 为空、`trackPointsFor(id)` 为空、`lapsFor(id)` 为空 ✅

**回归风险**：低。`deleteRide` 是唯一删除入口（活动详情页删除按钮）；清除全部数据走 `SettingsRepository.clearAll`（本身即全表清理）。

**后续建议**：可在 `TrackPoints`/`Laps` 的 `activityId` 上启用数据库层 `ON DELETE CASCADE`（Drift 支持 `references(..., onDelete: KeyAction.cascade)`）作为第二道防线。

## D-02 GPX 导入的活动名保留 `.gpx` 后缀（中：功能）

**发现用例**：ST-D04 —— "GPX 导入活动名去掉 .gpx 后缀且类型为导入"

**现象**：导入 `晨骑记录.gpx` 后，活动名为 `晨骑记录.gpx`，列表中出现多余后缀。

**根因**：Dart **raw string** 中的正则写成了 `r'\.gpx\$'`：`\$` 表示**字面量美元符**，因此该正则要求文件名以 `.gpx$` 结尾，永远不匹配 → 替换无效。

**影响**：导入活动名不整洁；同类"文件名清洗"逻辑（导出时也有正则）存在同样风险。

**修复**：抽出可测的纯函数，避免正则转义陷阱：

```dart
/// 去掉文件名末尾的 .gpx（大小写不敏感），并清理空白
static String stripGpxExtension(String fileName) {
  var n = fileName.trim();
  final lower = n.toLowerCase();
  if (lower.endsWith('.gpx')) {
    n = n.substring(0, n.length - 4);
  }
  return n.trim();
}
```

`GpxIo.importGpx` 改为 `final baseName = Gpx.stripGpxExtension(picked.$1);`

**验证**：ST-D04 —— `stripGpxExtension('晨骑记录.gpx') == '晨骑记录'`，且导入后 `name`/`type` 正确 ✅

**回归风险**：低。导出侧的清洗正则 `r'[^\w\u4e00-\u9fa5\-]+'` 保留（用于非法字符替换，语义正确）。

## D-04 记录页 `dispose()` 中使用 `ref` 导致异常（严重：稳定性）

**发现用例**：ST-U02 —— "摘要选'再骑一段'→回到记录中且不落库"（用例卸载页面时暴露）

**现象**：离开记录页（或页面被销毁）时抛出：

```
Bad state: Cannot use "ref" after the widget was disposed.
  at _RecordPageState._persistDraftIfActive (record_page.dart:127)
  at _RecordPageState.dispose (record_page.dart:94)
```

**根因**：`dispose()` 中调用 `_persistDraftIfActive()`，其内部使用 `ref.read(activityRepositoryProvider)` 写草稿；而 Riverpod 规定 `ConsumerState` 在销毁后不可再访问 `ref`。

**影响**：崩溃日志/红屏（debug）、草稿写入失败，**崩溃恢复（RCD-07）能力失效**——记录中退出页面时草稿可能没落库。

**修复**：在 `initState` 中缓存仓库引用，`dispose` 路径不再触碰 `ref`：

```dart
late final ActivityRepository _repo;   // dispose 阶段不能再用 ref

@override
void initState() {
  super.initState();
  _repo = ref.read(activityRepositoryProvider);  // 仅此处读取一次
  _loadDraft();
  _loadPrefs();
}

void _persistDraftIfActive() {
  if (_m.isActive) {
    _repo.saveDraft(...);            // 不再使用 ref
  }
}
```

**验证**：ST-U02 通过（卸载页面不再抛异常）；ST-U01 记录闭环通过 ✅

**回归风险**：中低。记录页内其它 `ref.read(activityRepositoryProvider)` 调用点统一改为 `_repo`，保证行为一致（`Provider` 返回同一实例）。

## D-05 ListTile 置于带背景容器中导致水波纹不可见（中：UI 质量）

**发现用例**：ST-U03（首页）、ST-U05（统计页）

**现象**：Flutter 框架断言：

```
ListTile background color or ink splashes may be invisible.
The ListTile is wrapped in a DecoratedBox that has a background color...
```

**根因**：`ListTile` 需要最近的 `Material` 祖先来绘制背景与水波纹；首页"最近活动"、统计页"当天活动"的 `ListTile` 直接放在带 `BoxDecoration(color: ...)` 的 `Container` 中（容器非 `Material`）。

**影响**：点击反馈（水波纹）缺失，视觉质量下降；debug 下产生框架告警，可能掩盖其他问题。

**修复**：用透明 `Material` 包裹 `ListTile`：

```dart
Material(
  type: MaterialType.transparency,
  child: ListTile(...),
)
```

修复位置：`home_page.dart`（`_row`）、`stats_page.dart`（`_dayCard`）。

**验证**：ST-U03 / ST-U05 通过，框架告警消失 ✅

**回归风险**：极低。活动列表使用 `Card`（本身是 `Material`），无需修改。
